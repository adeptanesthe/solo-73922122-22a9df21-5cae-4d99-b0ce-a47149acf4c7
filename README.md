# 笔顺订正工作台（Flask + Canvas）

学生写出字形后，老师用尽量少的动作示范如何订正**笔顺**。在米字格画布上对着范字临摹，
系统按原始书写方向计算离散 Fréchet 距离来配笔，求出最少的 **移笔 / 删笔 / 补笔** 动作序列，
可逐步播放、可一键采纳“下一步移笔/删笔”并按实际笔序重算；支持标记必须保留的笔，
保留要求无法满足时给出“无解”。

学生**少抬一次笔**、两笔被画布记成一笔时，老师还能对任意一笔**未标保留**的实写笔试拆：
系统在可行切法中把两段较大 Fréchet 距离降到最低，在画布上预览拆出的两笔；采纳后该笔被
替换为两段并都标为保留，再按新的实写笔序重算修订。

## 用 Docker Compose 启动

```bash
docker compose up --build
```

然后打开：

- <http://localhost:8000>
- 或 <http://localhost:5000>（Compose 额外把宿主 5000 映射到容器 8000，兼容 Flask 默认端口习惯）

镜像用 gunicorn 跑 `app.server:app`，带 `/healthz` 健康检查。

## 本地直接运行

```bash
pip install -r requirements.txt
python run.py                 # 默认 0.0.0.0:8000，可用 PORT 覆盖
# 打开 http://127.0.0.1:8000
```

## 使用流程

1. 顶部选择范字（内置 **一 十 人 八 大 口 土 木**，均附标准笔序，见 `app/data/characters/`）。
2. 在米字格中按住拖动书写；最多 10 笔，前端会把每笔精简/等弧长重采样到 **≤64 点**，坐标统一到 **1000×1000 共用网格**。
3. 拖动右上角滑块设定 **离散 Fréchet 上限**（默认 180/1000 网格单位，内置范字与正常临摹的同笔距离约 30–80，异笔通常 ≥260）。
4. 点 **求最优修订**：显示最少动作总数与「移 / 删 / 补」计数，并列出每一步。
5. 用 **播放 / 上一步 / 下一步 / ⏮** 逐步观看：
   - 移笔：蓝色高亮 + `from → to` 标记，笔画顺序徽标重排（几何位置不变，变的是笔序）；
   - 删笔：红色残影提示后移除；
   - 补笔：对应范字笔画以**紫色虚线**（带流动动画）示意；求解后所有缺笔也会先以淡虚线标出。
6. 点 **采纳下一步：删除/移动…**，该动作真正作用于实写笔画，随后前端自动请求，
   **按当前实际笔序重新求解**；右侧记录已采纳动作。可反复采纳直到只剩补笔示范。
7. 每行笔画可勾选 **保留**：保留笔不会被建议删除或移动（行内“删除”按钮也会禁用）。
   若保留笔找不到达标范字笔画，或保留笔的先后顺序与范字笔序冲突，页面直接显示 **无解** 与原因。
8. 笔迹增删、保留项或阈值一变，旧建议立即失效（同步清空、禁用采纳）；若已求过解会自动重算。
9. 没有笔迹时可点 **填入示例笔迹（含典型错误）** 快速体验：示例稳定包含顺序错误、多余笔和缺笔。
10. **试拆一笔（少抬一次笔）**：在“实写笔画”列表给任意一笔**未标保留**的笔点 **试拆**
    （点数 < 4、已是保留笔或已达 10 笔上限时按钮自动禁用并提示原因）。
    - 后端枚举所有切点 `k` 与相邻范字笔位对 `(j, j+1)`，要求两段各至少 2 个点、
      合起来**按原顺序保留全部采样点和坐标**（不重采样、不反转），两段距离都在上限内，
      且与已有保留笔一起按实写顺序各占不同范字笔位；
    - 在可行切法中最小化两段距离的较大者（minimax，平局再比距离和、更早切点、更早笔位对），
      画布用青绿 / 琥珀两色叠加预览两段，并标出切点与各自匹配的范字笔位；
    - 点 **采纳试拆结果**：仅把所选笔替换成两段，两段都标为保留，随后**按新的实写笔序重新求解**；
      点 **取消预览** 或改动范字 / 笔迹 / 保留项 / 上限，旧预览立即失效；
    - 无解（无相邻笔位可匹配、与保留笔冲突）或拆分后超过十笔时，面板给出中文原因并保留原笔迹。
11. 可点 **填入并笔示例（两笔被记成一笔）**：该示例把范字前两笔带抖动后首尾相接成一条连续点列，
    专用于体验试拆；采纳后修订代价降为 0。

## 算法说明

### 配笔：按原方向的离散 Fréchet 距离

`app/core/frechet.py` 的 `discrete_frechet(P, Q)` 是标准 O(p·q) 动态规划，
从首点走到末点，**不反转**任何一条曲线，因此撇/捺、逆序笔画不会被当作同向。
只有 `distance ≤ threshold` 的“实写笔 × 范字笔”才进入兼容矩阵。服务端直接对收到的
≤64 点序列计算离散 Fréchet（点数量上限正好把 DP 限制在 64×64）。

### 最少动作：带“不动主干（backbone）”的掩码 DP

范字有 `N` 个笔序槽位，成稿与范字**按笔序一一对应**：每个槽位要么放一笔兼容的实写笔，
要么记一次补笔；没被使用的实写笔记一次删笔。

- 一次“移到任意笔序位置”收费 1。
- 相对顺序与目标槽位一致的若干实写笔可以**不动**，构成递增主干；其余被使用的笔每笔移动一次。
- 对一个确定的配笔方案，最少移笔数 = 使用笔数 − 包含全部保留笔的最长递增子序列长度。

DP（`app/core/planner.py`）按实写当前顺序逐笔处理，状态为
`(最后一条主干槽位 last, 已占用范字槽位掩码 mask)`，每笔三选一：

| 选择 | 代价 | 约束 |
| --- | --- | --- |
| 删除 | 1 | 保留笔禁止 |
| 移动使用 `mv(j)` | 1 | `j` 兼容且未被占用；不约束主干顺序；保留笔禁止 |
| 不动/主干 `bb(j)` | 0 | `j > last`、兼容、未占用 |

结尾对每个未占用槽位加 1 次补笔。`N,K ≤ 10`，掩码仅 `2^10`。
保留笔被强制走 `bb`：既不能删也不能移动；若 DP 无可达终态即 **无解**，
并区分“保留笔无兼容范字笔画”和“保留笔顺序冲突”两种中文原因。

### 可播放步骤与“下一步”

由最优决策先产出删除步，再对剩余笔重算“含全部保留笔的最大强制 LIS”作为固定主干，
用确定性的插入构造 `move_operations_to_target`（已用穷举 1..8 全排列 + 随机用例验证：
每次都恰好得到目标顺序、每个移动笔只动一次且无空操作）。移动/删除步的 `from/to/index`
与前端 `applyMove`（先 `splice(from,1)` 再插入结果下标 `to`）严格同一语义，
因此预览逐步应用与老师采纳完全一致。每个“下一步”都经性质测试验证：采纳后重新求解的最优值
**恰好下降 1**。补笔步直接携带范字点列供虚线绘制。

### 试拆：把误并的一笔拆回两笔（`app/core/splitter.py`）

老师选的是一笔**未标保留**的实写笔。设该笔有 `n` 个采样点，试拆枚举全部切点
`k = 2 … n-2`，把点列无损切成 `points[:k]` 与 `points[k:]`（各 ≥2 点，不重采样、不反转，
两段并集与原点列逐点相等）。对每个切点枚举相邻范字笔位对 `(j, j+1)`：

1. 两段按书写方向分别与范字第 `j`、`j+1` 笔算离散 Fréchet，且都 `≤ threshold`；
2. 已标记保留的笔按实写顺序分为“拆之前 / 拆之后”两组锚点，要求存在一条严格递增的
   范字笔位序列：前置保留笔槽位 `< j`、两段占 `j, j+1`、后置保留笔槽位 `> j+1`，
   即拆出的两段与所有保留笔各占**互不相同**的范字笔位（`N ≤ 10`，用小型集合 DP 判定）。

在全部可行 `(k, j)` 中最小化 `max(dA, dB)`（两段距离的较大者），平局依次按
`dA+dB`、更早切点、更早笔位对决策，保证结果确定。无解时区分三类中文原因：
无任何相邻笔位可匹配、保留笔彼此顺序冲突、存在相邻匹配但与保留笔无法共处。
拆分后超过 10 笔、目标笔已保留或点数不足 4 时直接拒绝，原笔迹不动。

前端在画布上用两色叠加预览两段并标出切点；**采纳**只做一次
`splice(index, 1, segA, segB)`，两段都置 `preserved=true`，随后按新的实写笔序重新求解。

## HTTP API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/` | 画布页面 |
| GET | `/healthz` | 健康检查 |
| GET | `/api/characters` | 范字清单 |
| GET | `/api/characters/<id>` | 某范字完整笔画点列 |
| GET | `/api/sample/<id>` | 确定性错误示例（供“填入示例”/测试） |
| GET | `/api/sample/<id>?merged=1` | 并笔示例：前两笔被记成一笔，专供试拆演示 |
| POST | `/api/plan` | 求最优修订 |
| POST | `/api/split` | 对指定未保留笔试拆，返回最优两段预览 |

`POST /api/plan`：

```json
{
  "character_id": "mu",
  "threshold": 180,
  "strokes": [
    {"uid": "s0", "preserved": false, "points": [[500, 395], "..."]}
  ]
}
```

也可用 `"model": [[[x,y], ...]]` 直接内联范字。返回 `feasible / reason / cost /
counts{move,delete,add} / steps[] / next_action / compatible / dist / assign` 等。
超出“≤10 笔 / 每笔≤64 点”等限制时返回 `feasible:false` 与中文原因。

`POST /api/split`：

```json
{
  "character_id": "mu",
  "threshold": 180,
  "stroke_index": 0,
  "strokes": [
    {"uid": "m0", "preserved": false, "points": [[500, 395], "..."]}
  ]
}
```

成功返回 `feasible:true` 与 `cut_index / worst_distance / sum_distance /
resulting_stroke_count / preserved_slots / segments[{part,points,points_count,slot,distance}]`，
其中两段 `points` 拼接后与目标笔原点列逐点相等；无解、超十笔、目标笔已保留或点数不足时
返回 `feasible:false` 与中文原因，调用方保留原笔迹。

## 目录结构

```
app/
  server.py              # Flask 路由与入口（/api/plan、/api/split）
  core/frechet.py        # 离散 Fréchet、等弧长重采样
  core/planner.py        # 最优修订 DP、强制 LIS、步骤构造
  core/splitter.py       # 试拆：切点/相邻笔位枚举、保留锚点 DP、minimax
  core/sample.py         # 确定性错误示例 + 并笔示例
  data/characters/*.json # 内置范字（1000 网格、标准笔序）
  templates/index.html
  static/css/style.css
  static/js/app.js       # 画布、交互、播放、采纳、试拆预览、失效/自动重算
scripts/
  build_characters.py    # 重新生成范字 JSON
  dom_smoke.mjs          # 可选 jsdom 关键操作冒烟脚本（含试拆全流程）
tests/                   # 43 个 unittest（算法 + 试拆 + Flask test client）
Dockerfile  docker-compose.yml  requirements.txt  run.py
```

## 已做的实测

- `python -m unittest discover -s tests`：**43/43 通过**（原 26 个 + 新增 17 个）。
  原有覆盖 Fréchet 方向性、交换=1 次移笔、多笔/缺笔/多余笔、移删补组合、保留锚定/冲突/
  无兼容笔无解、数量上限，以及 120 组随机“下一步必使最优值−1”和 60 组“整段步骤到达终态”
  性质测试、完整 HTTP 采纳重算循环；新增试拆测试覆盖：
  - 并笔示例在 7 个多笔范字上都能拆回相邻的前两个笔位，两段点列拼接与原笔**逐点相等**、
    各 ≥2 点，采纳后重算代价 **0**；
  - 保留笔不可试拆、点数 <4 / 超 10 笔 / 序号非法被拒绝；
  - 阈值过紧、两段只能对上**非相邻**笔位、保留笔无兼容笔位、保留笔顺序冲突均返回“无解”；
  - 保留锚点位于拆分前后时仍能正确占位；
  - **60 组随机**用例下返回的较大距离与独立暴力枚举（全部切点 × 全部相邻笔位对）的
    minimax 最优值完全一致，切点也一致；结果两次调用确定不变；
  - HTTP 层 `/api/split` 的成功、保留拒绝、十笔上限、坏序号、采纳后 `/api/plan` 代价为 0。
- 启动与 Docker CMD 完全相同的 **gunicorn `app.server:app`**，用 urllib 跑通全部 7 个多笔范字的
  “并笔示例 → `/api/split` → 采纳两段 → `/api/plan` 代价 0”HTTP 循环，并验证低阈值返回中文“无解”。
- 用 **jsdom + Canvas2D 桩**加载真实页面和运行中的服务（`scripts/dom_smoke.mjs`）：
  原有流程（示例 cost=3、保留冲突“无解”、两次采纳到终态、播放、保留勾选失效自动重算）之外，
  新增并笔示例载入、试拆按钮启用规则、预览面板（切点/相邻笔位/点数/worst 距离）、
  改阈值使旧预览失效、再次试拆并采纳后笔数 +1 且两段均为保留并带“拆出”标记、
  按新笔序重算 cost=0、低阈值试拆显示“无解”，连续多轮全程无页面脚本错误。
- 用 Pillow 按前端同款配色渲染试拆预览成图人工核对：青绿/琥珀两段分别对应木的横、竖，
  切点白圈落在两段之间；并数值核对切点恰为点列中最大抬笔跳跃处，两段 Fréchet 与报告值一致。

运行可选 DOM 冒烟（需要先有 jsdom）：

```bash
npm install jsdom
BASE=http://127.0.0.1:8000 node scripts/dom_smoke.mjs
```
